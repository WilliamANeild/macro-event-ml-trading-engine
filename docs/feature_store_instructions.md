Hey, whoever is working on the feature store — this is basically what needs to happen. The schema (`src/engine/features/schemas.py`) and the basic builder (`src/engine/features/builder.py`) already exist, but right now the builder only computes 1-day returns per symbol and that's it. The experts are running on nearly empty feature vectors so this is kind of blocking the whole system from producing real signals. The FRED loader (`src/engine/data/fred_loader.py`) pulls macro data and the Yahoo loader (`src/engine/data/yahoo_loader.py`) pulls prices — both work fine, they just need to feed into way more features. There's a full feature engineering plan at `docs/feature_engineering_plan.md` with exact column names, formulas, and window sizes for everything I'm about to describe, so reference that as you go. Here's what needs to be built: First, expand the return features — add 5-day, 20-day, and 60-day returns per symbol using `returns.iloc[-N:].sum()`, named like `{symbol}_return_5d`, `{symbol}_return_20d`, `{symbol}_return_60d`. Second, add volatility features per symbol — 20-day and 60-day realized vol (annualized with `std * sqrt(252)`), vol of vol (std of rolling 20-day vol over 60 days), and a vol z-score (`(current_20d_vol - 60d_mean_vol) / 60d_std_vol`), named like `{symbol}_vol_20d`, `{symbol}_vol_60d`, `{symbol}_vol_of_vol`, `{symbol}_vol_zscore`. Third, drawdown features — current drawdown as `price / rolling_60d_max - 1` and days in drawdown (consecutive days below rolling high), named `{symbol}_drawdown` and `{symbol}_drawdown_days`. Fourth, cross-asset correlations — 20-day and 60-day rolling correlations between SPY-TLT, SPY-GLD, SPY-HYG, SPY-EEM (when SPY-TLT correlation turns positive, the 60/40 hedge breaks down, that's a critical regime signal), named like `corr_SPY_TLT_20d`, `corr_SPY_GLD_60d`, etc. Fifth, dispersion features — within-sleeve dispersion (std of returns across instruments in a sleeve like defense, shipping, etc.) and cross-sleeve dispersion (std of sleeve-average returns), named like `dispersion_defense_20d`, `dispersion_cross_sleeve_20d`. High within-sleeve dispersion means single-name alpha opportunity, low means just use ETFs. Sixth, the FRED loader needs its `DEFAULT_SERIES` expanded from 5 to at least 17 series — add VIXCLS (vix), DGS2/5/10/30 (yields), T10Y2Y and T10Y3M (curve slopes), DFF (fed funds), DFII10 (real rate), T5YIE and T10YIE (breakevens), T5YIFR (forward inflation), BAMLH0A0HYM2 and BAMLC0A0CM (credit spreads), DCOILWTICO and DCOILBRENTEU (oil), DTWEXBGS (USD index). Then compute derived features from those: yield curve slope plus a binary inversion flag, credit spread (HY OAS minus IG OAS), real rate momentum (20-day change), oil spread (brent minus WTI for geopolitical premium), USD momentum (5d and 20d changes), and VIX z-score (rolling 60-day). Seventh, all features need robust z-scores using `z = (value - rolling_median) / rolling_MAD` with a 60-day window so everything is comparable across scales. Eighth, weekly aggregation — the system rebalances weekly so convert daily features to weekly: sum returns over the week, take last day's value for vol/correlations/macro levels, sum daily changes for macro changes. Build it roughly in that order since each piece is testable on its own. Everything goes in `src/engine/features/builder.py` (expand the `FeatureBuilder.build()` method), the FRED expansion goes in `fred_loader.py`, and the output format stays the same — just more keys in the `FeatureRow.values` dict. Naming convention is `{symbol}_{metric}_{window}` for per-instrument stuff and `{metric}_{window}` for cross-asset. The existing tests should still pass and you should add tests that verify feature count increases, values are finite, and z-scores have mean around 0. Use the `SyntheticDataGenerator` for testing since it produces enough history for rolling windows. Check `docs/feature_engineering_plan.md` for the complete spec with all ~330 features and `docs/data_series_reference.md` for all the FRED series with descriptions.
